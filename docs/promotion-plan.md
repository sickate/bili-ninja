首屏文案建议：

>
> 在 Chrome 侧边栏完成操作，保留原始音画数据，处理在本机完成。

首批推广优先验证“同一 BV 的多个分 P 音频合并成一个可离线听的文件”这一场景，同时展示带声音的 MP4 导出能力。

目标用户是使用电脑 Chrome、需要整理知识讲解、访谈或语言材料的用户。产品页应明确以下范围，避免宣传超出实现：

- 音频输出为 AAC / M4A，保留原始压缩数据，不转码；当前不直接输出 MP3。
- 多 P 音频合并仅适用于同一 BV 下所选分 P，不包括不同 BV、UP 主合集或推荐列表。
- 视频导出每次处理一个分 P，输出 H.264 + AAC 的有声 MP4。
- 清晰度取决于当前账号实际可用的播放权限，不绕过付费试看或 DRM。
- 当前最低要求为 Chrome 116；其他浏览器需实际验证后再宣称支持。
- 单个画面流或音频流上限 512 MB，单次导出合计上限 1 GB；长内容可能需要减少分 P 或降低清晰度。
- 处理时保持视频页和侧边栏打开。

技术细节以当前 [README](../README.md) 和 [隐私政策](../PRIVACY.md) 为准。开源、本机处理、无广告、无遥测作为信任依据。

## 4. 安装与更新教程

### 4.1 发布 ZIP 安装

通过六步实际截图说明：

1. 从官网下载 ZIP，解压到准备长期保留的文件夹。
2. 复制 `chrome://extensions`，粘贴到 Chrome 地址栏打开。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择**直接包含 `manifest.json` 的文件夹**。
6. 固定 Bili Ninja，打开普通 BV 视频页，点击扩展图标开始使用。

注意两种目录结构的区别：

- 官网发布 ZIP：解压后直接选择包含 `manifest.json` 的目录。
- GitHub 源码：选择项目中的 `extension/` 目录。

不能把源码安装中的“选择 extension 文件夹”直接照搬给发布 ZIP 用户。Windows 和 macOS 的解压层级应分别通过实际操作截图验证。

### 4.2 常见问题与手动更新

教程解释选错目录、移动或删除安装目录、没有固定图标、打开了不支持的视频页面等常见问题。说明清晰度与账号权限相关，并展示可用的失败提示及处理步骤。

官网 ZIP 安装需要手动更新：下载新版，将新版扩展文件替换到原安装目录，在 `chrome://extensions` 点击该扩展的重新加载按钮，再重新打开视频页。官网提供版本记录和更新说明。

### 8.2 CLI 操作方案

本节保留首次配置方法供审查；常规官网内容发布使用 stage/activate，不需重跑这些 DNS 命令。未来确需改解析时另行核对授权、现值和回退记录。

macOS 可按阿里云官方文档安装：

```sh
brew install aliyun-cli
```

使用已授权且具有必要 DNS 权限的身份配置 CLI。凭据在执行环境配置，不写入本仓库或命令示例。

先只读查询，按返回的 `TotalCount` 处理分页，并备份相关现有记录：

```sh
aliyun alidns DescribeDomainRecords \
  --DomainName instap.net \
  --PageNumber 1 \
  --PageSize 500
```

核对 maru 的公网地址、现有站点、www 记录和解析线路。已有记录需要修改时使用 `UpdateDomainRecord`，不存在时才使用 `AddDomainRecord`。

以下为占位示例，实际参数必须取自重新查询和部署核对的结果：

```sh
aliyun alidns UpdateDomainRecord \
  --RecordId '<现有www记录ID>' \
  --RR www \
  --Type A \
  --Value '<maru公网IPv4>' \
  --TTL 600 \
  --Line '<现有解析线路>'
```

TTL 应结合实例支持范围和原记录确定。保留旧值与记录 ID，用于必要时恢复；修改后检查权威解析、HTTPS、产品页和 ZIP 下载。其他服务的记录不属于本次网站上线的修改范围。

maru 上先检查现有 Web 服务，使用独立站点配置和静态目录部署。裸域是否跳转到 www、证书覆盖范围及是否需要新增解析，由部署 agent 核对后实现。
