# Instap 官网开发与部署计划

日期：2026-11-11。依据 `docs/promotion-plan.md`，本次范围是官网开发、安装包分发与 maru 部署，不包含渠道发帖。

## 目标与范围

- 发布 `https://www.instap.net/` 公司首页及 `/bili-ninja/`、`install/`、`privacy/`、`changelog/`。
- 同站提供本地图片、脚本、样式与版本化 ZIP，不依赖公共 CDN；手机提示电脑 Chrome 安装并支持复制地址。
- 产品能力和限制遵循 README；隐私正文以 PRIVACY.md 为唯一来源。没有确认的邮箱、商店条目、客户案例不编造。
- ZIP 包只包含 extension 资源。构建自动核对 manifest，生成版本、大小、SHA-256 和发布信息。
- 显式将允许的 UTM 参数传递到 ZIP 请求。日志只代表请求，不能宣称独立用户、安装或导出成功。

## 方案与依赖

采用无运行时依赖的静态 HTML/CSS/JS，源文件放入 website/，构建产物独立放入忽略目录。部署使用 maru 现有 Web 服务，先只读检查主机、站点、证书、DNS 和接入条件。通过版本目录和原子切换发布，保留旧目录和原配置用于回退。只调整本次域名的必要配置。

## 验收与验证

1. 运行仓库 npm test 与 npm run package；检查 ZIP 根目录 manifest、文件白名单、版本、大小和 SHA-256。
2. 构建并检查站内链接、资源、页面路径、隐私正文、移动端提示、键盘交互、来源参数及无外部运行依赖。
3. 浏览器检查桌面和手机布局、下载与复制操作；已有演示媒体标明为测试媒体，不冒充真实安装截图。
4. 尽可能使用干净 Chrome 配置从官网 ZIP 加载，验证首次使用、单 P、多 P 和有声视频；无法验证的系统或步骤如实保留未验收状态。
5. 发布前确认 maru 公网 IP、现有 DNS、HTTPS 和其他站点；保存当前配置与发布目录指向。若无需 DNS 调整则保持现状。
6. 发布后检查 HTTP 跳转、TLS、全部页面和静态资源；实际下载 ZIP 并独立计算校验值，与本地及页面比对。
7. 提交、推送与远端 CI 状态分别报告。未部署或未验收的项目不宣称完成。

## 部署与回退

只有在连接和当前站点情况确认后才选定 maru 发布目录与 Web 服务配置。先上传新版本、验证配置，再原子切换，失败则恢复上一版本指向与已备份配置，重新检查 Web 服务。DNS 若确需修改，先保存记录 ID、原值、线路和 TTL，回退时恢复原记录。生产连接、凭据不写入仓库、产物或页面。
