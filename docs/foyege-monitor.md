## 运行与停止

先单次验收，受限时退出码为 2，状态仍写入本地：

```sh
python3 scripts/monitor-foyege.py --date 2026-11-15 --once
```

主 Agent review 后才可启动持续任务：

```sh
python3 scripts/monitor-foyege.py --date 2026-11-15
```

停止相同日期的任务：

```sh
python3 scripts/monitor-foyege.py --date 2026-11-15 --stop
```

停止文件持续生效；明确恢复时使用 `--resume`。支持 SIGTERM、SIGINT。停止检查通常在一秒内生效；正在进行的 HTTP 请求最长等待 20 秒。每天 23:59:59 后不再启动下一周期/请求；午夜前已经在途的请求可能到超时后才退出。旧日期再次运行直接写 expired，不改为监测次日。日期要求严格 `YYYY-MM-DD`，不能省略。

持续在线主机可在独立私有目录部署相同 `scripts/` 与 `artifacts/` 布局，并由主 Agent 用普通用户的 systemd transient unit 管理本日任务；不得放进 Nginx 静态目录。这里不自行安装、创建服务或启动后台任务。主 Agent 需要独立记录实际启动、停止、检查时间和部署结果。

## 状态、基线及去重

私有状态保存在 `artifacts/foyege-monitor-2026-11-15/state.json`；Git 已忽略整个 `artifacts/`。目录权限 0700，原子替换的状态文件 0600。进程使用同目录 `monitor.lock` 的 `flock`，同日期只能启动一个；不依靠可能过期的 PID 文件解锁。`STOP` 文件只请求停止，不按 PID 杀其他进程。

成功检查按发布时间分页读取公开投稿列表，扫描到前一日或列表结束，逐条通过 view 接口复核当日视频归属和发布时间。检查跨页、排序、结构、时间一致性；不完整结果丢弃，不建立空基线。每周期最多 100 页，达到上限记失败。此上限仅是保护，实际当前首个列表请求已经失败。

第一次成功检查会把当天所有可读取视频（包括开始运行前已经发布的视频）写入 `baseline_bvids`，同时加入 `pending_review`，避免将较早已发视频静默排除。后续按 BVID 去重，重启复用状态，同一视频不会再次产生新发现记录。`videos` 中保留标题、链接、发布时间和首次发现时间，供主 Agent 核对。

`pending_review` 是人工待核对队列，不是留言或通知回调。脚本没有发送、自动评论、浏览器操作、唤醒主 Agent 或执行外部命令的能力。会话结束后，持续运行最多只会留下状态与日志，不能保证主 Agent 及时留言。任何评论都需要主 Agent 在可用的已登录浏览器中核对新视频并执行；不得将“已发现/待核对”当作“已评论”。

`last_check.status: error` 以及具体 kind 区分网络、HTTP、API、风控、数据不完整等问题。失败保留上一次真实成功基线和待核对项；`successful_checks` 不递增。进程退出后最后状态是历史记录，是否仍在运行还应核对真实进程/服务状态。
